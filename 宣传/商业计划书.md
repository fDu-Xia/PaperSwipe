## 1、项目介绍&团队介绍

### 1.1 一句话介绍

PaperSwipe 是一款 **AI 驱动的论文发现与阅读管理工具**：用户只需说清楚自己的研究方向，AI 就会持续从 Semantic Scholar、arXiv、OpenAlex 等权威学术源里找到最值得读的论文，压缩成一张可正反翻转的知识卡片，用户像刷短视频、刷交友软件一样四向滑动完成筛选——左滑跳过、右滑收藏、上滑标重点、下滑标已读。筛选出来的论文会自动进入个人文献库，AI 还会结合研究目标、DDL 和空闲时间自动规划阅读日程，并实时呈现全球研究热点。

一句话总结产品理念：**把"找论文"从 Search（你主动搜索、逐篇验证）变成 Discover（AI 先认识你，主动把最合适的论文推给你）。**

### 1.2 核心产品形态

- **当前形态**：手机优先、零构建的 Web H5（打开即用，无需安装），已完成向 iOS 原生 App 的技术验证（基于 Capacitor 的混合壳跑通，正在推进真原生化以满足 App Store 商业化上架要求）。
- **四大功能模块**：
  1. **Explore** — AI 认识你，主动发现论文，四向滑动 5 秒判断
  2. **Library** — 划走的论文自动三栏归档（感兴趣 / 重点 / 已读），支持标签筛选、BibTeX / Zotero 一键导出
  3. **Schedule** — AI 自动规划阅读周计划，长按拖拽即可跨日期调整，AI 对话助手随时回答"今天最值得读哪篇"
  4. **Trending** — 实时全球研究热点榜，按领域追踪爆发方向与引用飙升论文

PaperSwipe 目前由一支小而精、全栈能力覆盖完整的团队自驱动完成从 0 到 1：

| 分工 | 职责 |

| 运营宣传 | 用户增长、社区运营（小红书 / 微信社群）、产品宣传物料与路演、用户反馈收集与闭环 |

团队成员均有扎实的工程背景与真实的科研/读论文经历——PaperSwipe 本质上是团队"为自己造工具"后发现的强共性需求，这也是我们对产品 PMF（Product-Market Fit）有信心的原因之一。团队目前保持精简高效，融资后计划优先补强后端工程（多租户与订阅系统）与增长两个方向。

## 2、痛点问题

### 2.1 读论文最贵的成本，从来不是"读"，而是"找"

对科研人员、研究生和技术从业者而言，一个几乎每天都在发生的场景是：

1. 打开 Google Scholar，搜一个关键词，出来几千篇结果；
2. 打开第一篇，人工翻译摘要，看完关掉；
3. 打开第二篇，翻译摘要，看完关掉……如此重复几十次；
4. 最终收藏了二十篇论文，标签打好、文件夹建好，感觉自己很努力；
5. 真正读完的：**0 篇**。

问题从来不是"论文不够多"，而是从"几千篇搜索结果"到"值得精读的那一篇"之间，隔着大量重复、低效、几乎没有信息增量的体力劳动。

### 2.2 具体拆解出的四个子问题

| 痛点 | 具体表现 |
|---|---|
| **信息过载，检索低效** | 关键词式搜索召回几千篇结果，人工逐篇判断相关性，认知负荷极高 |
| **摘要阅读门槛高、耗时长** | 英文摘要专业术语密集，非母语用户需要反复翻译，5~10 分钟才能判断一篇论文是否值得深读 |
| **收藏即遗忘** | 文献管理软件（Zotero / Mendeley / EndNote）擅长"管理已收藏的"，但对"选出来之后什么时候读、按什么顺序读"完全没有解决方案，收藏夹变成论文坟场 |
| **热点感知滞后** | 需要每天刷 Twitter / X、逛 arXiv 才能感知领域动态，个人很难持续跟踪全球研究前沿，容易错过关键工作或重复造轮子 |

### 2.3 谁在承受这些痛点

- **在读研究生 / 博士生**：文献综述、开题、日常追踪都需要高频筛选论文，是最高频、最痛的用户群体；
- **高校教师 / 研究员**：时间稀缺，需要在有限时间内判断"这篇论文是否值得团队投入精力"；
- **企业研发 / 算法工程师**：需要持续跟踪最新论文以指导工程决策，但没有精力做系统性文献调研；
- **科技媒体 / 行业分析师**：需要第一时间感知全球研究热点以支撑内容生产和判断。

这是一个**长期存在、高频发生、但被现有工具系统性忽视**的问题——现有产品要么专注"搜索"（Google Scholar、Semantic Scholar 官网），要么专注"管理"（Zotero、Mendeley），中间"发现 + 快速判断 + 阅读规划"这一层始终缺失。

## 3、产品方案

PaperSwipe 用四个环环相扣的模块，完整覆盖"发现 → 判断 → 归档 → 阅读 → 追踪热点"的全流程，让"找论文"这件事第一次拥有了系统性的产品化方案。

### 3.1 Explore — AI 先认识你，再替你发现论文

- 不需要每次重新搜索关键词：用户只需用自然语言描述研究方向，AI 自动拆解为精准检索词，实时联通 Semantic Scholar / arXiv / OpenAlex 三大学术源；
- 每篇论文被压缩成一张双面知识卡片：**正面**一句话讲清核心贡献（Hook），**背面**结构化拆解问题、方法、结果、创新点、适合谁读、推荐理由；
- **四向滑动**完成决策：左滑跳过、右滑收藏（Interested）、上滑标重点（Priority）、下滑标已读（Read），同时支持按钮和方向键，5 秒左右即可对一篇论文做出去留判断；
- 无 LLM Key 时自动降级为本地证据抽取算法，保证功能永远可用，不依赖单一供应商。

### 3.2 Library — 划走的每一篇论文，都有了真正属于你的家

- 三栏自动分类（感兴趣 / 重点 / 已读），进度一目了然；
- AI 自动提炼主题标签，支持标签筛选与全文搜索，秒速定位历史论文；
- 长按卡片可快速归档、删除或一键安排进阅读日程；
- 支持 BibTeX 导出与 Zotero 联动，无缝接入用户已有的文献工作流，不做"信息孤岛"。

### 3.3 Schedule — AI 帮你规划阅读，论文不再躺在收藏夹吃灰

- 告诉 AI 研究目标、DDL 和空闲时间，AI 自动从 Library 中挑选论文、按优先级铺满一周阅读计划；
- **长按卡片、拖拽到其他日期框即可调整排期**，交互像原生日历一样自然；
- 内置 AI 对话助手，可直接提问"今天最值得读的论文是哪篇？""帮我规划这个方向的阅读 roadmap"，AI 给出可执行的答案与理由；
- 收藏不再是终点，而是真正被读完的起点。

### 3.4 Trending — 今天，全世界都在看什么

- 实时全球热点榜，按领域滚动更新高热度论文；
- 一键展开某个热门 Topic 下的代表性论文，快速建立领域全貌；
- 引用飙升提醒，重要工作出现的第一时间感知；
- 支持 My Fields（只看自己领域）与 Global（看全球大势）双视角切换，用户始终站在信息最前沿而不是滞后半个月才知道。

### 3.5 产品差异化定位

| 维度 | Google Scholar / 官网检索 | Zotero / Mendeley 等文献管理器 | **PaperSwipe** |
|---|---|---|---|
| 核心范式 | Search（主动搜索） | Manage（被动管理已收藏文献） | **Discover（AI 主动发现 + 推荐）** |
| 判断效率 | 需逐篇打开、人工翻译摘要 | 不涉及判断环节 | AI 摘要卡片 + 滑动决策，5 秒判断 |
| 收藏后怎么办 | 无解决方案 | 归档但不规划阅读 | AI 自动规划阅读日程，防止吃灰 |
| 热点感知 | 无 | 无 | 实时全球热点榜 |
| 交互体验 | 桌面网页表单 | 桌面客户端 | 手机优先、类短视频/社交软件的沉浸式滑动体验 |

PaperSwipe 不是要替代 Zotero，而是补上了"从海量论文到值得精读那一篇"之间、此前完全靠人力硬扛的那一段——这正是我们最大的差异化壁垒。

## 4、市场机会&商业模式

> 本节聚焦市场规模与竞争格局；具体商业模式设计详见第 6 部分「商业模式」。

### 4.1 目标市场规模（TAM / SAM / SOM）

- **TAM（全球潜在市场）**：据 UNESCO《科学报告》估算，全球科研人员数量已超过 880 万人；叠加全球在校研究生（保守估算超过 2000 万人），构成"高频读论文"人群的核心基本盘。
- **SAM（可服务市场）**：以中文/英文为主要工作语言、有移动端学习习惯的科研与研发人群。仅中国教育部数据显示，我国在读研究生规模已突破 388 万人（2023 年），是天然的早期种子用户池；叠加国内企业研发、AI/互联网行业算法工程师群体，SAM 保守估算在千万级用户量级。
- **SOM（可获取市场）**：立足"AI + 学术"垂直赛道，优先从高校实验室、研究生社群、科技从业者社区切入，目标在产品成熟后 2~3 年内在中文科研用户群体中拿下有意义的渗透率（细分市场的头部心智），再逐步向英文市场扩展。

同时，学术产出本身仍在加速增长——arXiv 官方数据显示其年新增论文提交量已超过 20 万篇，是十年前的两倍以上，"信息过载"这一根本痛点只会持续加剧，为 PaperSwipe 提供了长期增长的市场基本面。

- **真实市场信号验证**：项目在黑客松路演现场收到了大量用户的正向认可，反复被验证的核心反馈是"这是一个真实痛点、我确实需要这样一个工具"，同时用户普遍认可"让枯燥的科研过程娱乐化、年轻化"这一产品理念，这也是团队坚定推进这个方向的重要信心来源；
- **早期社区冷启动已跑通**：目前正在运营小红书账号，持续发布产品内容与使用场景，已收到大量积极反馈，验证了"科研 + 娱乐化交互"这一心智在真实用户中具备传播力，为后续规模化获客积累了初步的内容与渠道基础。

### 4.2 竞争格局

| 类型 | 代表产品 | 局限 |
|---|---|---|
| 学术搜索引擎 | Google Scholar、Semantic Scholar 官网、PubMed | 仍是关键词搜索范式，判断效率完全依赖人工 |
| AI 辅助阅读工具 | Elicit、Scite、Consensus 等 | 多为桌面网页端问答工具，缺少移动端沉浸式发现体验与阅读规划闭环 |
| 文献管理软件 | Zotero、Mendeley、EndNote | 擅长管理已收藏文献，不解决"发现"与"何时读"问题 |
| 滑动式论文发现工具 | Zinote（个人开发者独立开发的产品） | 仅实现"按话题抓取论文摘要 + 支持滑动"这一单点功能，停留在 Demo 层面，没有 Library 归档、Schedule 阅读规划、Trending 热点追踪等后续配套生态，也没有形成完整的产品闭环 |
| **PaperSwipe** | — | 唯一把"发现 → 判断 → 归档 → 阅读规划 → 热点追踪"做成移动端一体化闭环的产品 |

现有产品之间高度割裂——用户需要同时打开 Google Scholar 搜索、翻译工具理解摘要、Zotero 管理收藏、Twitter 追踪热点，PaperSwipe 用一个 App 把这条链路完全打通，这是我们进入市场的核心楔子（wedge）。

### 4.3 商业模式概览

采用移动端订阅制商业模式为主线，即 **Freemium（基础功能免费获客）+ Pro 订阅（核心付费点：无限量发现与 AI 阅读规划）**，辅以机构版和数据/API 授权作为中长期增长曲线。详见第 6 部分。

## 6、商业模式

### 6.1 收入结构总览

| 收入来源 | 目标用户 | 说明 |
|---|---|---|
| **Pro 订阅（核心收入）** | 高频研究生 / 科研人员个人用户 | 解锁无限量论文发现、AI 阅读规划、AI 对话助手、优先级更高的摘要质量与生图能力，App Store / Google Play 标准订阅制内购 |
| **机构 / 实验室版** | 高校实验室、企业研发团队 | 团队共享文献库、管理者仪表盘、批量席位授权，按坐席数订阅 |
| **数据与 API 授权** | 出版方、文献管理工具、科研信息服务商 | 基于全网热点追踪能力，输出领域趋势报告或开放检索/推荐 API |
| **生态联动（远期）** | Zotero 等文献管理工具、学术会议/期刊 | 导出/联动场景中的轻量级合作分佣或联合推广 |

### 6.2 免费 / 付费边界设计（Freemium）

- **免费层**：每日/每周有限次数的 AI 论文发现与摘要卡片、基础的 Library 归档与导出功能——保证核心体验对所有用户可用，作为获客与口碑传播的基本盘；
- **Pro 订阅层**（月付 / 年付两档，年付享折扣）：
  - 无限量论文发现与滑动判断
  - AI 自动阅读规划（Schedule 智能排期 + AI 对话助手无限次数）
  - 更高质量的 LLM 摘要与可选的论文视觉图生成
  - 多设备同步、云端历史记录
  - 优先客服支持

初步定价假设（待市场验证后调整）：面向中国用户参考 18~28 元/月或 128~198 元/年的价格带，面向海外用户参考 4.99~7.99 美元/月，与同类知识工具/生产力订阅产品（如 Notion AI、Readwise）保持相近心理定价区间。

### 6.3 为什么这个商业模式能跑通

1. **高频刚需**：读论文是研究生/科研人员的日常刚需，付费意愿建立在真实的时间成本节省之上（"5 秒判断一篇论文"直接对应可感知的时间价值）；
2. **成本结构健康**：核心成本是 LLM API 调用与学术源检索，均为按量计费，随收入同步增长，不存在重资产/高固定成本负担；
3. **多层收入曲线**：个人订阅打底、机构版做规模化增长、数据授权做长期毛利增厚，避免单一收入来源的脆弱性；
4. **App Store 生态天然适配**：订阅制 + 移动端高频使用场景，是 App Store / Google Play 生态中被验证效果最好的商业模式之一。

## 7、融资需求

### 7.1 本轮融资目标

PaperSwipe 目前已完成核心产品 MVP 的开发与早期验证，具备了从"团队自驱动打磨"迈向"规模化增长"的产品基础。本轮计划启动**天使轮/种子轮融资**，用于完成账号体系与订阅系统建设、iOS/Android 原生 App 上架，并启动首批规模化获客，验证付费转化与留存数据，为下一轮融资建立清晰的增长曲线。

### 7.2 资金用途分配

| 用途 | 占比 | 说明 |
|---|---|---|
| 研发投入 | 40% | 多租户后端与账号体系、iOS/Android 原生化、订阅内购接入、PDF 全文解析等核心功能建设 |
| 服务器与 API 成本 | 20% | LLM 摘要调用、学术源检索、图片生成等按量计费的核心运行成本 |
| 市场推广与获客 | 25% | 高校社群运营、内容营销（小红书/知乎/公众号）、KOL 合作、应用商店 ASO |
| 团队扩编 | 10% | 优先补强后端工程与增长/运营岗位 |
| 合规与其他 | 5% | 应用商店合规审核、法务、财务等基础运营开支 |

### 7.3 里程碑目标

- 完成账号体系与订阅系统建设，iOS App 正式上架 App Store；
- 付费用户规模与 Pro 订阅转化率达到可支撑下一轮融资叙事的健康水平；
- 建立稳定的次周/次月留存曲线，验证"高频刚需 + 高留存"的核心假设；
- 完成至少 1 个高校实验室或企业研发团队的机构版试点合作。

### 7.4 除资金外的期望支持

- 高校实验室、研究生社群等早期种子用户渠道资源；
- 学术数据源、LLM 算力/API 层面的资源对接与成本优化支持；
- 面向 App Store 出海与合规（内购、隐私合规等）的顾问资源。

---

*本商业计划书基于 PaperSwipe 项目当前代码实现、产品官网（introweb）信息整理撰写，市场数据为基于公开资料的合理估算，具体财务与定价条款将在尽调阶段进一步核实与调整。*
